## Design Context

### Users
Developers working for long periods inside terminal windows, including narrow VS Code terminals. They use Argo to maintain one readable conversation while switching among coding CLIs, inspecting tools and subagents, and scrolling through long technical answers.

### Brand Personality
Calm, precise, and capable. Argo should feel like a focused professional instrument: confident enough to expose complex activity, restrained enough that the conversation remains comfortable to read.

### Aesthetic Direction
Use an editorial, terminal-native hierarchy inspired by the Codex transcript reference supplied by the project creator. Give user prompts a distinct, softly shaded full-width row; group assistant output below with quieter metadata and generous vertical separation. Preserve Argo's cyan identity for navigation, status, links, and selected state rather than applying it uniformly to all content. Support dark terminals first while retaining semantic, theme-compatible terminal colors.

Avoid noisy boxes around every message, excessive cyan-on-dark decoration, undifferentiated user/assistant typography, and formatting that separates ordered-list markers from their content.

### Design Principles
1. Conversation roles must be distinguishable at a glance without relying on text labels alone.
2. Content has priority over chrome: metadata is quieter, while prompts and responses receive deliberate spacing and grouping.
3. Long sessions must remain easy on the eyes in both wide terminals and constrained VS Code panes.
4. Markdown structure must survive wrapping; list markers, headings, code, and continuation lines should read as one coherent block.
5. Use color semantically and sparingly, with legibility that does not depend on one terminal palette.
